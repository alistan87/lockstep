# Spec-vs-Implementation Audit Report

**Verdict:** PASS

**Reason:** All three upheld findings are minor and either latent or peripheral — an argparse usage-error exit code collision, an unguarded exception path in contracts-module loading, and an unreachable no-spill-dir branch in context-file interpolation — with no blocker and no major finding showing a violated MUST, frozen exit code, or guarantee on a live execution path.

## Upheld Findings

| Severity | File | Claim |
|---|---|---|
| Minor | `src/lockstep/cli.py:407` | Argparse usage errors exit with status 2, which SPEC §3 freezes to mean "gate BLOCK," so a mistyped invocation is indistinguishable from a quality gate blocking the run. |
| Minor | `src/lockstep/contracts.py:118` | An exception raised while executing a `contracts_module` (e.g. SyntaxError or a module-body error) escapes contract resolution, so `lockstep verify` crashes with a traceback instead of reporting a finding and exiting 5. |
| Minor | `src/lockstep/interpolate.py:228` | `fence_context_file` silently embeds a full over-cap `spec.context` file into the prompt with no spill and no error when `spill_dir` is `None`, unlike `render_template`'s handling of the identical case for interpolated values. |

## Recommended Actions

- Subclass `ArgumentParser` (or override `error`/`exit`) in `cli.py` to map usage failures onto `EXIT_CONFIG` (7), keeping exit code 2 reserved for gate BLOCK.
- Broaden the exception guard in `contracts.py`'s `_load_module`/`resolve_contract` to catch `Exception` generally and re-raise as `ContractError`, turning a bad contracts module into an ordinary §6 finding instead of a crash.
- Raise `InterpolationError` in `fence_context_file` when content exceeds `max_interp_chars` and `spill_dir` is `None`, mirroring `render_template`'s behavior for consistency, even though the branch is currently unreachable in live runs.

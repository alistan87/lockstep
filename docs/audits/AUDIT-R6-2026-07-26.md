# Spec-vs-Implementation Audit Report

**Verdict:** PASS

**Reason:** No blocker findings, and no upheld finding violates a stated MUST, a frozen exit code, or a stated guarantee. The engine reviewer's "major" lineage-head issue is real but fail-safe (a narrow crash window causes extra re-runs and a misleading warning, never a missed detection or a wrong result), so it is upheld at **minor** severity alongside four other minor/nit items.

## Upheld Findings

| Severity | File | Claim |
|---|---|---|
| minor | `src/lockstep/roles.py:739` | Lineage-head fingerprint is recorded before heal rollback runs and is never refreshed after `_heal()` restores the tree; a crash between restore and the next node completion causes resume to misread lockstep's own rollback as an external edit. |
| minor | `src/lockstep/roles.py:697` | The `CANCELLED` marker is checked after ordinary spawns but not after either corrective re-spawn, so cancelling a node during a corrective attempt is misreported as a contract-validation failure instead of `failed(cancelled)`. |
| minor | `src/lockstep/roles.py:695` | A record's `error` set when a budget trip interrupts the corrective re-spawn is never cleared, leaving a stale "contract validation failed" message on a record that later resumes and completes `done`. |
| minor | `src/lockstep/cli.py:123` | `--dry-run` double-counts a node's exclusive tokens, so a non-readonly harness node explicitly declaring `exclusive: ["tree"]` is reported as serialized against itself. |
| nit | `src/lockstep/taskgraph.py:408` | The §6.9 exclusive-collision lint and dry-run plan treat `role: "approval"` nodes as harness executor nodes holding the `tree` token, producing false collision warnings and a bogus `executor=` line for nodes the engine never routes through an executor. |
| nit | `src/lockstep/taskgraph.py:239` | The Policy seam has no verify-time call site, though SPEC §8.1 states `allows` is consulted at verify time AND immediately pre-execute; kept at nit since v1's `AllowAllPolicy` is a documented no-op, so no run behaves differently today. |

## Recommended Actions

1. Refresh `fingerprint_detail` immediately after `self.workspace.restore(...)` in `_heal()`, or defer `_record_fingerprint` for a gate until its verdict is a durable pass.
2. After each corrective `executor.execute(...)` call, check for `CANCELLED` and short-circuit to a cancelled outcome before contract validation (mirror the initial-spawn paths).
3. Clear `rec.error = None` in `_run_node_safe`'s `BudgetTripped` handler (or on transition to `done`) so stale error messages don't survive into completed-run audit records.
4. Dedupe exclusive tokens in `cli.py`'s dry-run plan by iterating `set(eff)`, matching the existing pattern in `taskgraph.py:410`.
5. Skip `role == "approval"` nodes when computing effective exclusive tokens in both the taskgraph rule-9 lint and `cli.py`'s `_print_plan`.
6. Thread a Policy into `verify_flow` (or `_do_verify`) and emit a named `policy-denied` error for verify-time `allows` checks, closing the gap before Policy implementations grow teeth.
